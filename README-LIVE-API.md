# Protected Market Data API

This backend exposes authenticated market-data datasets for the terminal UI. It does not silently replace provider failures with generated values.

## Modes

- **Simulated mode:** local demonstration data generated by the frontend.
- **Provider mode:** data returned by the protected backend. Each response reports `connected`, `degraded`, or `unavailable` status.

The UI separately reports `connecting`, `connected`, `degraded`, or `failed` connection state.

## Required configuration

```bash
cp .env.example .env
```

Set both required secrets:

```env
FINNHUB_API_KEY=your_finnhub_key
BACKEND_API_KEY=your_long_random_backend_key
```

The server refuses to start without `BACKEND_API_KEY`.

Optional resilience controls:

```env
ALLOWED_ORIGINS=http://localhost:3000,http://localhost:5173
RATE_LIMIT_WINDOW_MS=60000
RATE_LIMIT_MAX=120
UPSTREAM_TIMEOUT_MS=8000
UPSTREAM_MAX_CONCURRENT=4
```

## Authentication

All `/api/*` endpoints require:

```http
X-API-Key: <BACKEND_API_KEY>
```

The supplied value is compared with the configured server key using constant-time comparison. `/health` is public and exposes configuration state only, never secret values.

## Response contract

Dataset endpoints return an envelope:

```json
{
  "status": "connected",
  "source": "finnhub",
  "asOf": "2026-08-03T00:00:00.000Z",
  "items": [],
  "errors": [],
  "metadata": {}
}
```

- `connected`: requested provider data was returned.
- `degraded`: some data was returned, but one or more instruments or services failed.
- `unavailable`: no usable items were returned.

Provider-mode errors do not trigger random-data fallback.

## Endpoints

| Endpoint | Behavior |
|---|---|
| `GET /api/indices` | Quotes for US-listed ETF proxies representing international benchmarks |
| `GET /api/heatmap` | US equity quotes and Finnhub `marketCapitalization` values |
| `GET /api/stocks/:symbol/candles` | Historical stock candles plus MA20, MA50, RSI, and MACD calculations |
| `GET /api/metals` | Quotes for US-listed commodity ETF proxies; not spot commodity prices |
| `GET /api/tape` | Buffered Finnhub WebSocket trade events |
| `GET /api/news` | Normalized Finnhub general-market news |
| `GET /api/sessions` | Static reference exchange sessions |
| `GET /health` | Server, provider, authorization, and trade-stream state |
| `POST /auth/validate` | Validates the configured backend API key |

## Instrument integrity

### Benchmark proxies

The index panel uses supported US-listed symbols rather than undocumented `INDEX:*` quote symbols:

| Display benchmark | Provider symbol |
|---|---|
| S&P 500 | SPY |
| NASDAQ 100 | QQQ |
| Dow Jones | DIA |
| FTSE 100 | EWU |
| DAX 40 | EWG |
| Nikkei 225 | EWJ |
| Hang Seng | EWH |
| Shanghai | ASHR |
| ASX 200 | EWA |
| Nifty 50 | INDA |

These are ETF proxies and are labeled as such in API metadata and the UI.

### Commodity proxies

The commodity panel uses GLD, SLV, PPLT, PALL, USO, BNO, UNG, and CPER. These are exchange-traded products quoted per share, not spot metals or futures contracts.

Bid and ask values remain `null` when the quote endpoint does not provide them.

### Trades

The tape consumes actual Finnhub WebSocket trade events. It reports event type `TRADE`; it does not fabricate or infer buyer/seller direction.

When the stream is disconnected or has not delivered trades, the endpoint reports a degraded or unavailable state with an empty item list.

## Resilience

The backend implements:

- TTL caching for provider responses
- bounded upstream concurrency
- upstream request timeouts
- client API rate limiting
- explicit partial-failure reporting
- WebSocket reconnect handling
- fail-closed server authorization

## Development

```bash
npm ci
npm run dev:all
```

Open `http://localhost:3000`, enter the **backend API key** in the toolbar, then switch to provider mode.

## Verification

```bash
npm run verify
```

This runs TypeScript checks, backend endpoint/authentication/resilience tests, frontend connection-state tests, and a production build. GitHub Actions runs the same gate on pull requests and `main`.

## Known provider constraints

- Finnhub account entitlements determine whether candle data is available.
- The session endpoint is static reference data and does not include holiday calendars.
- GitHub Pages hosts only the frontend; provider mode requires a separately deployed HTTPS backend.
